# 프로젝트 삭제 기능 결정 기록

## D1. Spring 소유 데이터의 삭제 정책

- 결정: 프로젝트와 연관된 Spring 소유 데이터를 함께 영구 삭제한다.
- 근거: 사용자가 프로젝트 삭제를 요청했고, 보관·복구 기능은 이번 범위에 포함하지 않는다.
- 삭제 대상: API 키, 레포지토리와 자격 증명, 참고 문서, Bugs, Issues, Issue-Bug 링크, 분석 결과, workflow runs, Issue branches, 프로젝트 행.
- 제외한 대안: 연관 데이터가 있으면 삭제를 거절하는 방식(B)은 사용자가 선택하지 않았다. 보관 상태 전환(C)은 별도 기능으로 다룬다.

## D2. Agent 소유 데이터와 실패 처리

- 결정: Agent Graph에 프로젝트 단위 정리 요청을 추가하고, 정리 실패 시 Spring 삭제를 중단한다.
- 근거: PCM·검색 인덱스·Git mirror는 Agent 소유이므로 Spring 삭제만으로는 프로젝트 자료가 남는다.
- 처리 순서: Agent 정리를 동기 호출로 성공시킨 뒤 Spring 소유 데이터를 삭제한다.
- 제외한 대안: Agent 데이터를 남기는 방식(B)과 Spring 삭제 후 최선 노력으로 정리하는 방식(C)은 잔존 데이터 또는 실패 은닉 위험 때문에 선택하지 않았다.

## D3. Admin 재확인 방식

- 결정: 프로젝트 이름을 정확히 입력해야 삭제한다.
- 근거: 영구 삭제의 오동작을 줄인다.

## D4. 삭제 성공 뒤 화면 상태

- 결정: 선택 프로젝트를 비우고 리포트 화면으로 이동한다.
- 근거: 다른 프로젝트를 임의로 선택하지 않는다.
