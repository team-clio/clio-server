# 프로젝트 생성 마법사 작업 개요

## 목적

사용자가 프로젝트 생성에 필요한 정보를 넓은 화면에서 단계별로 입력하고, 생성 직후 분석 준비까지
한 흐름에서 마칠 수 있게 한다.

## 현재 상태

- 사이드바의 `프로젝트 추가`를 누르면 작은 모달이 열린다.
- 모달은 프로젝트 이름과 설명만 입력받는다.
- 프로젝트를 만든 뒤 저장소 연결과 참고 문서 업로드를 각각 별도 화면에서 해야 한다.
- Admin에는 프로젝트 생성, 저장소 연결, 문서 업로드 API 연동이 이미 있다.

## 문제

- 작은 모달은 입력 공간과 안내가 부족해 생성 과정의 전체 범위를 알기 어렵다.
- 코드 분석에 중요한 저장소와 참고 문서를 생성 과정에서 안내하지 않는다.
- 생성 후 사용자가 다음에 어디로 이동해 무엇을 설정해야 하는지 스스로 찾아야 한다.
- 여러 API 요청 중 일부가 실패할 때 완료 범위와 재시도 방법을 명확히 보여 주는 흐름이 없다.

## 개선 방향

프로젝트 추가 진입점을 넓은 단계형 마법사 화면으로 연결한다. 각 단계는 현재 위치, 입력 목적,
필수 여부를 표시하며 이전·다음 이동을 지원한다. 마지막에는 입력 내용을 확인하고 프로젝트 생성 및
후속 설정 결과를 안내한다.

검토할 기본 흐름은 다음과 같다.

1. 기본 정보 입력
2. 코드 저장소 설정
3. 참고 문서 설정
4. 입력 내용 확인 및 생성 완료

정확한 단계 구성, 선택 단계의 건너뛰기 정책, 실제 생성 시점, 실패 복구 방식, 완료 후 이동 위치는
plan 단계의 결정 포인트로 제시한다.

## 작업 범위

- `clio-admin`의 프로젝트 추가 진입 방식 변경
- 데스크톱에서 넓은 본문 영역을 사용하는 반응형 마법사 UI
- 단계 표시, 이전·다음·취소, 입력 검증과 오류 안내
- 기존 프로젝트·저장소·문서 API를 조합한 생성 흐름
- 생성 성공 후 새 프로젝트 선택 상태 반영
- TypeScript 검사, ESLint, 빌드와 Storybook 기반 화면 검증

## 제외 범위

- Spring API와 데이터 모델 변경
- GitHub 등 외부 서비스에서 저장소를 검색하거나 권한을 확인하는 기능
- 새로운 문서 형식 지원
- 기존 프로젝트 설정·문서 관리 화면의 전면 재설계
- 생성 중 입력 내용을 서버 초안으로 저장하는 기능

## 완료 기준

- 프로젝트 추가를 누르면 작은 모달 대신 넓은 단계형 생성 화면이 열린다.
- 사용자는 단계별 안내에 따라 기본 정보와 선택 설정을 검토할 수 있다.
- 필수 입력 검증과 API 오류가 해당 단계에서 이해할 수 있게 표시된다.
- 성공한 생성 결과가 프로젝트 목록과 현재 선택에 반영된다.
- 좁은 화면에서도 단계 이동과 주요 입력을 사용할 수 있다.
- `npm run typecheck`, `npm run lint`, `npm run build`가 통과한다.
