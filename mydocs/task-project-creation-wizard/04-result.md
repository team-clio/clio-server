# 프로젝트 생성 마법사 작업 결과

## 완료 상태

구현과 정적 검증을 완료했다. 실제 브라우저 시각 점검은 실행 환경의 브라우저 연결 초기화 실패로
수행하지 못했으며 수동 확인 항목으로 남겼다.

## 변경 내용

### 생성 진입

- 사이드바의 작은 프로젝트 생성 모달을 제거했다.
- `프로젝트 추가`를 누르면 App 본문 전체를 사용하는 독립 생성 화면으로 이동한다.
- 작성 내용이 있을 때 취소하거나 다른 화면으로 이동하면 이탈 확인창을 표시한다.

### 4단계 마법사

1. 기본 정보: 필수 이름과 선택 설명을 입력한다.
2. 저장소: 저장소 하나를 선택적으로 연결하고 분석·제외 경로를 지정한다.
3. 참고 문서: PDF·Markdown 파일 여러 개를 선택하고 제목을 편집한다.
4. 검토·생성: 입력 요약을 확인하고 프로젝트와 후속 설정을 생성한다.

단계 표시기, 이전·다음·취소, 필수값·URL·파일 형식 검증을 제공한다. 저장소와 참고 문서는 모두
건너뛸 수 있다.

### 생성과 실패 복구

- 마지막 단계에서 프로젝트를 먼저 생성한다.
- 저장소와 문서는 프로젝트 ID를 사용해 순서대로 등록한다.
- 생성된 프로젝트를 현재 프로젝트로 선택한다.
- 모든 요청이 성공하면 버그 리포트 화면으로 이동한다.
- 후속 설정 일부가 실패하면 프로젝트와 성공 항목을 유지한다.
- 실패 항목만 재시도하거나 프로젝트 설정으로 이동할 수 있다.

### 문서와 Storybook

- 생성 화면 기본 상태 Storybook 스토리를 추가했다.
- `clio-admin/API_UI_CHANGES.md`에 새 생성 흐름과 실패 정책을 기록했다.
