# 프로젝트 생성 마법사 결정 기록

## 위임

- 2026-08-23: 사용자가 모든 결정 포인트를 plan의 추천안대로 진행하도록 위임했다.

## D1. 화면 표시 방식

- 결정: App 본문 전체를 사용하는 독립 화면으로 구현한다.
- 근거: 넓은 입력 공간과 안정적인 반응형 구조를 제공하고 단계 확장에도 대응하기 쉽다.
- 제외: 전체 화면 모달과 오른쪽 패널은 기존 화면 위에 탐색 계층을 추가하고 가용 폭이 작아 제외했다.

## D2. 단계 구성

- 결정: `기본 정보 → 저장소 → 문서 → 검토·생성` 4단계로 구성한다.
- 근거: 성격이 다른 저장소와 문서를 분리하면서 제출 결과를 마지막 단계에서 이어서 보여 줄 수 있다.
- 제외: 3단계는 분석 설정이 복잡해지고, 5단계는 완료 화면만을 위한 이동이 추가되어 제외했다.

## D3. 프로젝트 생성 시점

- 결정: 마지막 검토 단계에서 프로젝트를 생성하고 후속 설정을 순서대로 실행한다.
- 근거: 중간 취소로 불완전한 프로젝트가 남는 일을 줄이고 제출 전까지 모든 입력을 자유롭게 수정할 수 있다.
- 제약: 후속 설정은 프로젝트 ID가 필요하므로 프로젝트 생성 성공 후에만 실행한다.
