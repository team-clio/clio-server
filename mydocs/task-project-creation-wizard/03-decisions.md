# 프로젝트 생성 마법사 결정 기록

## 위임

- 2026-08-23: 사용자가 모든 결정 포인트를 plan의 추천안대로 진행하도록 위임했다.

## D1. 화면 표시 방식

- 결정: App 본문 전체를 사용하는 독립 화면으로 구현한다.
- 근거: 넓은 입력 공간과 안정적인 반응형 구조를 제공하고 단계 확장에도 대응하기 쉽다.
- 제외: 전체 화면 모달과 오른쪽 패널은 기존 화면 위에 탐색 계층을 추가하고 가용 폭이 작아 제외했다.

## D2. 단계 구성

- 결정: `기본 정보 → 저장소 → 문서 → 검토·생성` 4단계로 구성한다.
- 근거: 성격이 다른 저장소와 문서를 분리하면서 제출 결과를 마지막 단계에서 이어서 보여 줄 수 있다.
- 제외: 3단계는 분석 설정이 복잡해지고, 5단계는 완료 화면만을 위한 이동이 추가되어 제외했다.

## D3. 프로젝트 생성 시점

- 결정: 마지막 검토 단계에서 프로젝트를 생성하고 후속 설정을 순서대로 실행한다.
- 근거: 중간 취소로 불완전한 프로젝트가 남는 일을 줄이고 제출 전까지 모든 입력을 자유롭게 수정할 수 있다.
- 제약: 후속 설정은 프로젝트 ID가 필요하므로 프로젝트 생성 성공 후에만 실행한다.

## D4. 저장소와 문서의 필수 여부

- 결정: 저장소와 문서는 모두 선택 사항으로 두고 건너뛰기를 허용한다.
- 근거: 문서 중심 분석이나 수동 버그 수집처럼 저장소 없이 시작하는 프로젝트도 지원해야 한다.
- 필수값: 프로젝트 이름만 생성 필수값으로 유지한다.

## D5. 최초 생성에서 지원할 연결 개수

- 결정: 저장소는 최대 1개, 문서는 여러 개를 지원한다.
- 근거: 첫 저장소 설정은 간결하게 유지하고 여러 참고 문서는 기존 업로드 경험과 동일하게 처리한다.
- 후속 작업: 추가 저장소는 프로젝트 설정 화면에서 연결한다.

## D6. 후속 설정 일부 실패 처리

- 결정: 생성된 프로젝트와 성공 항목은 유지하고 실패 항목의 재시도 또는 설정 화면 이동을 제공한다.
- 근거: 성공한 작업을 보존하며 자동 삭제로 인한 데이터 손실과 중복 요청 위험을 피한다.
- 완료 조건: 프로젝트 생성 성공은 명확히 알리고 후속 설정별 결과를 구분한다.
