# 프로젝트 관리 API 작업 결과

## 완료한 범위

- `GET /api/v1/projects`
  - `ListResponse.items`에 전체 프로젝트를 반환한다.
  - 프로젝트 이름 오름차순으로 정렬한다.
- `POST /api/v1/projects`
  - 이름과 선택적 설명을 받아 프로젝트를 생성한다.
  - 성공 시 `201 Created`와 생성된 프로젝트를 반환한다.
- 프로젝트 응답에 ID, 이름, 설명, 상태, 생성·수정 시각을 제공한다.
- 빈 이름과 필드 길이를 Bean Validation으로 검증한다.
- 앞뒤 공백과 대소문자를 무시한 프로젝트 이름 중복을 `409 Conflict`로 거부한다.
- 정규화한 이름에 DB unique 제약을 적용해 동시 생성 충돌도 방지한다.

## API 응답 형식

프로젝트 목록은 다음 형태다.

```json
{
  "items": [
    {
      "id": 1,
      "name": "Clio Admin",
      "description": "Admin project",
      "status": "ACTIVE",
      "createdAt": "2026-08-12T08:00:00Z",
      "updatedAt": "2026-08-12T08:00:00Z"
    }
  ]
}
```

## 검증 결과

- 명령: `./gradlew test`
- 결과: 성공
- 검증 항목:
  - 프로젝트 생성과 응답 필드
  - 전체 목록 반환
  - 이름 오름차순 정렬
  - 빈 이름의 `400 VALIDATION_FAILED`
  - 대소문자·공백을 무시한 중복 이름의 `409 CONFLICT`
  - 기존 전체 테스트 회귀

## 남은 과제

- 운영 데이터가 존재하는 환경에 적용하기 전에 기존 프로젝트의 `normalized_name`을 채우는 데이터
  마이그레이션이 필요하다. 현재 저장소에는 마이그레이션 도구가 없으므로 이번 범위에서는 다루지 않았다.
- 프로젝트 상세 조회·수정·비활성화 API는 후속 작업이다.
- 사용자별 프로젝트 접근 권한은 인증·인가 작업에서 다룬다.
- 관리자 화면은 이 API 응답의 프로젝트 ID를 선택 상태로 사용하도록 후속 연동이 필요하다.
