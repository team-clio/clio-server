# 프로젝트 관리 API 작업 개요

## 목적

관리자 화면과 버그·이슈 API가 공통으로 사용할 프로젝트 식별자를 제공한다. 사용자는 프로젝트 목록을
조회하고 새 프로젝트를 생성할 수 있어야 한다.

## 현재 상태

- `Project` 엔티티와 `ProjectRepository`가 있다.
- 버그 리포트와 이슈 API는 경로 변수로 `projectId`를 요구한다.
- 프로젝트를 조회하거나 생성하는 HTTP API는 없다.
- 따라서 클라이언트가 유효한 `projectId`를 서버에서 얻을 공개 경로가 없다.

## 문제

프로젝트 API가 없으면 관리자 화면이 프로젝트 이름과 식별자를 자체적으로 관리해야 한다. 이 경우 화면의
선택 상태와 서버 데이터가 달라질 수 있고, 프로젝트별 버그·이슈 조회를 안정적으로 시작할 수 없다.

## 개선 방향

프로젝트 도메인에 공개 HTTP 표면을 추가한다.

- 프로젝트 목록 조회
- 프로젝트 생성
- 생성 요청 검증
- 존재하는 엔티티를 외부 계약과 분리하는 요청·응답 DTO
- 컨트롤러와 서비스 동작을 검증하는 테스트

## 작업 범위

이번 작업은 관리자 화면 연동에 필요한 최소 API만 다룬다.

- `GET /api/v1/projects`
- `POST /api/v1/projects`
- 응답에 프로젝트 ID, 이름, 설명, 상태, 생성·수정 시각 제공
- 생성 시 이름 필수 검증

## 제외 범위

- 프로젝트 상세 조회·수정·삭제·비활성화
- 저장소와 프로젝트 컨텍스트 연결
- 사용자별 프로젝트 접근 권한
- 관리자 화면 변경
- 인증·인가

## 완료 기준

- 프로젝트를 생성한 뒤 목록에서 조회할 수 있다.
- 잘못된 생성 요청은 공통 오류 형식으로 `400 Bad Request`를 반환한다.
- 새 테스트와 기존 전체 테스트가 통과한다.
